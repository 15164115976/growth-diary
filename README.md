# 春生夏长 · 花鸟鱼虫生长记录小程序

> 名字出自《史记·太史公自序》：「夫春生夏长，秋收冬藏，此天道之大经也。」

给花、鸟、鱼、虫记日子的小本子。每天固定角度拍一张，时间会把照片连成一段会动的记录。

## 快速开始

1. 打开**微信开发者工具** → 导入项目 → 目录选 `growth-diary`
2. AppID 填你自己的（`project.config.json` 里现在是 `touristappid`，测试号也能跑，但相机/相册在测试号上受限，建议换成自己的 AppID）
3. 编译运行。首次启动会自动生成 4 条示例记录（雷龙 / 龟背竹 / 玄凤 / 独角仙），方便直接看效果

> 想先看界面：直接用浏览器打开 `preview/index.html`，是五个界面的高保真预览，可以点、可以调参数、幻灯片会自己播。

## 四条需求分别做在哪

### 1. 主页与「优先进入上一次的记录」

`pages/index/` —— 顶部是一张「继续观察」大卡，永远指向你最近在看的那条记录；下面按 **花 / 鸟 / 鱼 / 虫** 四类分组横滑。

启动直达逻辑在 `pages/index/index.js` 的 `maybeAutoEnter()`：

- `last`（默认）—— 冷启动自动进上次那条记录的详情页
- `fixed` —— 固定进某一条（可在「我的」里选）
- `home` —— 停在首页

只跳一次，从详情返回不会再把你弹走（用 `app.globalData.autoEntered` 标记）。三种模式在「我的 → 打开小程序时」随时切换。

### 2. 图标 + 叠底参考拍照

**图标**：每条记录有一个 emoji 图标（按分类给出候选，比如鱼是 🐟🐠🐡🦈🦐…），也可以选一张照片当图标。详情页点头像即可换，或进编辑页换。

**叠底参考**（`pages/capture/`，这是核心）：

```
<camera>              ← 实时取景
  <image class="ref">  ← 上一次的照片，opacity 0.38 + blur(3px) + 提亮降饱和
  <view class="grid">  ← 三分线
  <view class="corners"> ← 四角对位标记
```

上一层照片被处理成「虚化浅色」压在取景框上，把实物对到虚影上，角度自然就一致了。配套细节：

- 浓度可调（20% / 38% / 55% / 75% 循环，设置页也能拉）
- 参考底可随时关闭
- 拍完进确认页，**拖动分割线**做本次/上次的前后对比，附带一句备注输入
- 没有相机的设备可以从相册选图，走同一套确认流程

关于「同层渲染」：`camera` 从基础库 2.4.4 起支持同层渲染，普通 `image` 能正常盖在上面。极少数老旧 Android 机型可能盖不住——真机上如果发现参考底不显示，升级微信客户端即可。

### 3. 养护手册 + 养护记录（独立入口）

`pages/care/` —— 一个页面两个页签，从详情页的三个按钮或底部栏进入：

- **养护手册**：按分类内置了 5 条专业要点（花：光照/浇水/施肥/换盆/常见问题；鱼：水质/水温/喂食/防跳/病症；鸟、虫同理），可折叠、可增删改，也能一键恢复默认
- **养护记录**：6 类快捷打卡（喂食、换水浇水、清洁、光照日照、用药除虫、其他），点一下 + 填备注就记下；上方按建议周期自动算「距上次几天」，超期标橙；下方是按日期分组的时间线，长按删除

### 4. 时间顺序幻灯片 + AI 过渡

`pages/slideshow/` —— 照片按拍摄时间升序播放，两层交替做**交叉溶解**，配合 **Ken Burns** 缓慢推近/拉远（推、拉逐张交替，避免单调）。顶部进度条、底部日期/第 N 天/距上张天数/备注。点击左右 26% 切上一张下一张，中间暂停。

**过渡的两档设计**（`utils/transition.js`）：

| 模式 | 做法 | 成本 |
|---|---|---|
| 本地（默认） | CSS 交叉溶解 + Ken Burns | 0，离线可用 |
| AI（可选） | 相邻两张交给生成式模型合成过渡视频，缓存后插播 | 需自建服务 |

AI 是**可插拔**的：不填接口地址就自动降级到本地过渡，界面不会报错。配置入口在「我的 → 幻灯片 → 过渡服务地址」。

服务端接口约定（骨架已写好在 `transition.js` 里，照着实现即可）：

```
POST {endpoint}/frames       multipart, field: file    -> { url }
POST {endpoint}/transition   json {from, to, duration} -> { videoUrl } 或 { taskId }
GET  {endpoint}/transition/{taskId}                    -> { status, videoUrl }
```

生成好的过渡视频会落盘缓存（最多 24 段，LRU 淘汰），同一对照片第二次直接播缓存。「我的」里可以查看条数和一键清除。

## 新增的四个能力

### ① 开机先识别：这次要记录谁

启动页换成了 `pages/identify/`。拍一张（或从相册选），交给识别服务判断**是花、鸟、鱼还是虫**，最好还能给出品种：

```
识别成功 → 「看起来是「鱼」· 七彩雷龙 · 可信度 86%」
        → 命中已有记录就显示「你记录过它，今天是第 31 天」
        → 点一下直接进详情，没记录过就一键新建
识别失败 → 不拦你，直接把你记录过的生物铺在下面让你挑
```

关键设计：**识别永远是加速入口，不能阻塞主流程**。没接识别服务、网络挂了、模型认不出，都退回到「我记录过的」+「新建」，跟没这功能时一样顺。

识别服务可插拔，两种接法：
- 云函数 `recognize`（推荐，见下方云开发部分）
- 自建接口：`POST {endpoint}/recognize`，multipart 字段 `file`，返回 `{ category, species, confidence }`，`category` 取 `flower|bird|fish|insect`

关闭方式：「我的 → 打开小程序时 → 先识别再进去」；想临时用一次，「我的 → 识别与云端 → 现在识别一次」。

### ② 相机随重力翻转

倒着拿时取景画面自动转 180°，UI 不跟着转。

- **不用加速度计的正负号判定**：iOS 和 Android 上报的 y 轴符号并不统一，写死符号就会出现「正常拿着反而被翻转」——这是最容易踩的坑。改成优先用 deviceMotion 的姿态角 `beta`（竖立 ≈ +90，倒置 ≈ -90，跨平台一致），退化到加速度计时把首次稳定读数当基准，只判断「相对基准翻转了没有」
- 进页面后有 900ms 静默期，期间只对齐基准、不触发翻转，避免画面刚出来就跳一下
- 连续 3 次采样一致才切换，防手抖
- 自动判断不合意时，取景页底部有「手动切换」，点一下即接管，不再自动干预
- 画面翻转只是 CSS `rotate`，光转画面不够——**拍出来的照片还是倒的**，所以保存前用离屏 canvas 把它转正（`utils/image.js` 的 `rotateImage`）
- 不想用就在「我的 → 拍摄 → 随重力翻转」关掉

### ③ Live 图：照片会动一下

小程序没有系统级 Live Photo，所以做的是「静图 + 一小段视频」的组合：

```
按快门 → takePhoto 拿静图（立刻）
      → 紧接着 startRecord 录 2.2 秒 → stopRecord 拿 mp4
      → 两张一起存，photo.live = { path, duration }
```

播放时静图先落定，700ms 后把视频叠上去播一遍，播完淡出——就是 Live Photo 那种「照片活过来」的观感。详情页点时间线里的照片、幻灯片自动播放时都会触发。

- 录制失败（没给麦克风权限、机型不支持）就只存静图，不报错、不阻塞
- 每段约 1–3MB，介意体积就在「我的 → 拍摄 → 动态图」关掉
- 幻灯片里带 Live 的那几张，底部会有个 `LIVE` 标记

### ④ 漂流瓶：默认不投，互动要双向同意

把一条记录打包成瓶子放进海里。**默认关闭**，必须在「我的」里打开「允许投放」，或者在详情页手动点「做成漂流瓶」并二次确认——不会在你不知情的情况下把东西发出去。

互动规则：

| 动作 | 是否需要对方同意 |
|---|---|
| 点赞 | 否，单向 |
| 订阅（关注这只生物的后续） | 否，单向 |
| 评论 | **是，必须双方同意** |

评论的授权流程：捞到瓶子 → 点「申请互动」→ 状态变 `pending` → 瓶子主人收到申请并同意 → 双方才能互相留言。没通过之前输入框根本不会出现。

技术上靠 `utils/bottle.js` 一层封装，两个通道：

- **云开发**（真实跨用户）：`cloudfunctions/bottle` 一个云函数承载 throw / pick / detail / like / subscribe / requestComment / respondConsent / comments / addComment / mine 十个动作
- **本地演示**（没开通云环境）：用内置样本跑通整套交互，点赞、订阅、申请评论都能点，申请后 1.4 秒自动「对方同意」方便走完流程

两条通道返回结构一致，页面代码不用判断走的是哪条。设置页会显示「云端已连接 / 当前为本地演示」。

## 影集与查看器

### 卡片左滑：置顶 / 排序 / 删除

影集里每张卡片都能左滑，露出「置顶 / 上移 / 删除」。长按还有一份完整菜单（含「下移」）。

顺序存在 `record.sortOrder`，`store.reorderRecords(ids)` 负责重排成连续的 0..n-1。不同分类的记录在影集里是一条统一的主序列，跟主页按分类分组是两套视图。

左滑做了两个细节：先判定横滑还是纵向滚动（纵向就让页面滚），拖动中临时关掉 `transition`，松手才回弹吸附。

### 打开后的查看器（slideshow）

| 操作 | 效果 |
|---|---|
| 左 26% 点击 | 上一张 |
| 中间点击 | 暂停 / 继续 |
| 右 26% 点击 | 下一张 |
| **向上滑** | 打开拍摄日历 |
| **向下滑** | 打开养护计划与最近打卡 |
| 点 LIVE | 播放这张的动态片段 |
| 横屏 | 画面整体转 90° 铺满，UI 不转 |

日历按月分组，有照片的日子标绿点，点一下直接跳到那张。

### 封面与图片编辑

**换封面**：详情页封面右上角「换封面」，可以从相册导一张，或把当前封面裁一裁；也可以一键恢复成「自动用最新照片」。自定义封面存在 `record.customCover`，`decorate` 里优先于最新照片。

**裁剪**：长按任意一张时间线照片 → 「裁剪调整」，进入 `pages/crop/`。支持拖动平移、双指缩放（1–5 倍）、五种比例（原图 / 1:1 / 3:4 / 4:3 / 9:16），导出走离屏 canvas，最长边 1440px。

坐标换算是这套东西的核心：图片中心固定在裁剪框中心，缩放以中心为原点，导出时把裁剪框四角反算回原图坐标，用 `drawImage` 九参数取样。

### 养护计划

养护页第三个页签「计划」，每种养护都能单独设置：

- **每 N 天**：1 / 3 / 7 / 30 天都行，填 0 或不开启就不提醒
- **每次用量**：比如「3 粒粮」「换 1/3 水」「稀薄液肥 1 次」

计划存在 `record.carePlan`，新建记录时按分类给一份合理默认（鱼是每天喂 3 粒、每 3 天换水；花是每 3 天浇透、每月施肥；鸟是每天换食清底盘；虫是每 3 天投喂、每 14 天换垫材）。

「今天该做什么」的到期判断、查看器下滑面板、养护记录页共用这一份计划，改一处到处生效。

## 接入云开发（识别与漂流瓶）

不接也能用，只是走本地演示。要真跑起来：

1. 开发者工具左上角「云开发」→ 开通 → 记下**环境 ID**
2. 填到「我的 → 识别与云端 → 云开发环境 ID」，重启小程序
3. 建 4 个集合，权限全部选**「仅创建者可读写」**：
   `bottles` / `bottle_interactions` / `bottle_consents` / `bottle_comments`
4. 右键 `cloudfunctions/bottle` → 上传并部署（云端安装依赖），`recognize` 同理
5. 给 `recognize` 配环境变量（云开发控制台 → 云函数 → 配置）：
   ```
   VISION_BASE_URL = https://api.deepseek.com/v1   （任意 OpenAI 兼容的视觉接口）
   VISION_API_KEY  = sk-xxx
   VISION_MODEL    = 支持图片输入的模型名
   ```

所有越权判断都在云函数里做：点赞计数用 `_.inc` 原子更新、`respondConsent` 校验 `ownerOpenid === OPENID`、`addComment` 校验 consent 是否 accepted。数据库规则设成「仅创建者可读写」，前端拿不到别人的数据。

## 数据怎么存

主体全本地，**不接云开发也能完整使用**：

- 结构化数据 → `wx.setStorageSync`（`gd_records_v1` / `gd_settings_v1`）
- 照片 → `wx.env.USER_DATA_PATH/photos/`（拍照后自动压缩到 82 质量再落盘）
- Live 片段 → `USER_DATA_PATH/lives/`，图标 → `icons/`，AI 过渡视频 → `transitions/`
- 漂流瓶演示状态 → `wx.getStorageSync`（`gd_bottle_state_v1`）

单条记录的照片数组只存路径和元信息，storage 不会撑爆。真要上云，把 `store.js` 里 `persistFile` 换成上传云存储即可，页面代码不用动。

## 真机运行要注意的五件事

1. **胶囊按钮避让**：`navigationStyle: custom` 之后，微信右上角的胶囊是浮在最上层的，自己画的按钮很容易被它压住。所有页面顶部内容统一从 `safeTop` 开始（胶囊下沿 + 8px，在 `app.js` 的 `measureLayout` 里算）。要调顶部布局请改 `safeTop`，别直接改 `statusBarHeight`。
2. **隐私协议**：小程序后台「设置 → 服务内容声明 → 用户隐私保护指引」里勾选**摄像头**、**麦克风**、**相册**。少了摄像头和相册，`camera` 和 `chooseMedia` 直接失败；少了麦克风，Live 录制会静默降级成纯静图（不崩，但没有动态）。
3. **域名白名单**：填了 AI 过渡或识别接口才需要，把域名加到 `request` / `uploadFile` / `downloadFile` 合法域名，必须 HTTPS。用云开发则不需要配域名。
4. **重力翻转的传感器差异**：极少数机型姿态角方向相反，会出现「正常拿反而转了」的情况——取景页点「手动切换」接管，或在「我的 → 拍摄」关掉。
5. **照片体积**：默认压缩质量 82，一天一张一年约 30–50MB。开了 Live 每张再加 1–3MB，介意就关掉动态图。

## 可以继续加的东西

- **收瓶箱**：`bottle` 云函数的 `pending` 动作已经写好（返回等我同意的申请列表），还差一个页面把它列出来
- **订阅消息**：订阅的瓶子有新照片时，用 `wx.requestSubscribeMessage` + 云函数定时推送提醒
- 跨记录的总影集（把所有记录的照片混在一条时间线上播）
- 照片的「首尾对比」并排视图（详情页时间线标题右侧留了位置）
- 生长数据曲线（记录每次的身长、叶数、冠幅，画折线）
- 多设备同步（记录本身搬上云数据库，`store.js` 换掉读写层即可）
